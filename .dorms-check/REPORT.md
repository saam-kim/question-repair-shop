- 지금 상태: 아직 판단 안 됨(interview·judge 필요)
- AI에게 이렇게 시켜주세요: `저장소의 LICENSE·README·배포 이력을 확인해 이미 공개된 이용 조건이 있는지 보고, 새 이용 조건과 충돌하면 알려줘.`

#### [medium] 응답이 비법 원문을 돌려주지 않음
- 무엇: 서버가 결과만 주지 않고 비법 지시문이나 정답 데이터 원문까지 통째로 돌려주면, 서버에 뒀어도 새는 것과 같아요.
- 지금 상태: 아직 판단 안 됨(interview·judge 필요)
- AI에게 이렇게 시켜주세요: `API 응답에 프롬프트 원문·정답 데이터 전체·내부 설정이 실려 나가지 않는지 확인하고, 화면에 필요한 결과만 내려보내게 고쳐줘.`

#### [medium] 무제한 호출 방지
- 무엇: 내 서버 기능을 아무나 무한정 부를 수 있으면, 남이 내 API 를 자기 앱처럼 쓰거나 내 비용을 쓰게 할 수 있어요. 호출 제한이나 로그인 확인을 두세요.
- 지금 상태: 아직 판단 안 됨(interview·judge 필요)
- AI에게 이렇게 시켜주세요: `핵심 API 에 호출 제한(rate limit)이나 로그인 확인을 추가하고, 외부 사이트에서 마음대로 부르지 못하게 출처 확인을 넣어줘.`

#### [low] 산출물 지문(해시) 기록
- 무엇: 배포물의 파일별 지문(해시)을 기록해 두면, 나중에 "이건 내 원본"임을 보일 근거가 돼요.
- 지금 상태: 아직 지문 기록 없음(protect apply 로 생성)
- AI에게 이렇게 시켜주세요: `dcheck protect apply 를 실행해 산출물 해시 매니페스트를 만들어줘.`

#### [low] 앱 화면 권리 표시
- 무엇: 앱 화면(푸터 등)에 만든 사람과 이용 조건 안내가 보이면, 쓰는 사람도 지켜야 할 조건을 알 수 있어요.
- 지금 상태: 아직 판단 안 됨(interview·judge 필요)
- AI에게 이렇게 시켜주세요: `앱 푸터나 정보 화면에 저작권 표시와 이용 안내 링크를 추가해줘. rights-profile 의 attribution 문구를 쓰면 돼.`


> 정직 고지: 난독화나 Base64 인코딩은 비밀이 아니에요. 브라우저로 전달된 코드·데이터는 공개된 것으로 봐야 해요. 이 트랙은 "완전 보호"를 약속하지 않아요. 서버 분리, 복제 비용 상승 조치, 권리·이용 안내, 증거 준비의 현재 상태를 구분해 보여줄 뿐이에요.
