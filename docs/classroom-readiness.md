# 질문수리소 — 수업 준비 점검 및 변경 내역

점검일: 2026-09-18. 아래 수정은 로컬 저장소에 반영했습니다. GitHub 푸시, Vercel 배포, 운영 Firebase 설정·보안 규칙 변경은 수행하지 않았습니다.

## 이번 검토에서 반영한 수정

| 항목 | 반영 내용 |
| --- | --- |
| 응답 방식 | 예/아니요를 독립된 응답 방식으로 추가. 작성·미리보기·응답·질문 수리·결과 내보내기에 적용 |
| 교과 표현 | ‘한 문항에 한 가지 내용만 묻기’, ‘특정 응답을 유도하지 않기’ 등 질문지 작성 유의점을 문장으로 안내 |
| 화면 | 화이트·선명한 블루·네이비, SVG 로고, 일관된 카드와 버튼, 모바일 배치, 수업 운영 가이드, QR 창 키보드 조작 |
| 인증 | Firebase 익명 인증과 기존 인증 복원을 기다린 뒤 접근. 임의의 로컬 UID를 실제 사용자처럼 사용하던 처리 제거 |
| 서버 권한 | 미인증 접근 차단. 교사는 본인 수업만 제어. 학생은 참여한 수업을 읽고 본인 조만 해당 활동 단계에서 수정 |
| 데이터 검증 | 예/아니요 값, 척도·단답형 값, 질문과 피드백 구조·문자 수 검사. 배정받지 않은 조에 대한 응답과 불완전한 완료 표시 차단 |
| 입장 | 인증 UID를 조 문서 ID로 사용. 여러 탭·재시도에서 같은 조 재사용. 코드 생성과 조 번호 할당을 트랜잭션으로 처리 |
| 진행 | 일시정지·종료 상태의 학생 수정, 응답 배정 이후 새 조 입장 차단. 수업당 최대 40개 조 |
| 리허설 | Firebase를 사용하지 않는 메모리 저장소. 실제 수업 단계와 학생 기록에 영향 없음. 닫으면 연습 내용 폐기 |
| 새로고침 | 주제·질문지·수리·응답·피드백 초안 복구. 서버에 제출한 응답 문항을 건너뛰고 계속 진행. 마지막 완료 처리 재시도 제공 |
| 저장 확인 | 서버가 확인하기 전의 임시 로컬 스냅샷으로 다음 화면에 넘어가지 않도록 수정 |
| 수업 관리 | 같은 브라우저에서 만든 수업 목록, 종료 수업 다시 보기, CSV 결과 다운로드, 종료 수업과 조 기록의 일괄 삭제 |
| 결과 해석 | 모두 ‘문제 없음’인 경우와 피드백 자체가 없는 경우를 구분 |

CSV에는 질문·응답·피드백·수리 이유와 응답 방식이 포함됩니다. 한글 Excel을 위한 BOM, 따옴표·줄바꿈 처리, 수식 실행 방지 처리를 적용했습니다. 인증 UID는 내보내지 않습니다.

## 검증한 범위

- `npm run build`: TypeScript 검사와 프로덕션 빌드.
- `npm run lint`: 오류 없음. 기존 상태 동기화 effect 관련 경고와 Firebase 번들 크기 경고는 별도 기능 오류가 아닙니다.
- `tests/yes-no.mjs`: 예/아니요 작성·미리보기·혼합 응답·수리·결과, 초안 복구.
- `tests/classroom.mjs`: 교사·학생 화면, QR/Escape, 입장, 최소 조 수, 일시정지·재개·종료 확인, 실패·재시도, 390/768/1440px 화면.
- `tests/export.mjs`: CSV 인코딩, 줄바꿈·따옴표, 수식 무력화, 인증 식별자 제외.
- `tests/security.mjs`: 실제 Firestore 규칙으로 역할별 허용·거부, 잘못된 응답·선택지 차단, 일시정지·종료 보호, 이전 버전 접근 차단, 삭제 검증. **40개 독립 클라이언트의 동시 입장**, 중복 탭, 40개 제한, 최대 3개 조에 대한 9개 문항의 응답·피드백·완료 처리 검증. 변경된 대상 조만 검증하여 누적 응답이 규칙 계산량 제한을 넘지 않도록 했습니다. 실제 앱의 조 배정 함수를 사용합니다.
- `tests/emulator-browser.mjs`: 데이터 접근부를 대체하지 않고 Firebase Auth·Firestore 에뮬레이터와 실제 앱 연결. 교사 1명/학생 2명 브라우저 환경에서 생성 → 입장 → 질문 → 응답·피드백 → 수리 → 결과 → 다운로드 → 종료 → 수업 목록 → 삭제를 통과했습니다. 새로고침과 중복 탭의 동일 인증 복원, 제출 중인 초안 및 제출한 문항 복원, 전체 리허설·초기화 전후 운영 대상 데이터 동일성도 확인했습니다.

Firestore 에뮬레이터의 동시 트랜잭션에서 충돌이 `permission-denied`로 반환되는 사례가 있었습니다. **에뮬레이터 연결 시에만** 수업 상태를 재확인하고 횟수 제한과 지연을 두어 재시도합니다. 프로덕션은 권한 오류를 재시도하지 않으며 서버 권한 규칙은 동일하게 적용됩니다. 에뮬레이터 통과가 실제 학교 Wi-Fi나 운영 서비스의 성능을 보장하지는 않습니다.

## 남아 있는 운영 조건

- 운영 Firebase의 익명 인증 설정·보안 규칙·Vercel 환경 변수는 이번에 조회하거나 변경하지 않았습니다. **운영 주소에는 아직 이 수정이 반영되지 않았습니다.**
- 조별 대표 기기 한 대, 수업을 만든 교사의 같은 브라우저를 사용합니다. 다른 기기로 교사 권한을 인계하거나 여러 조원 기기를 한 조에 연결하는 기능은 없습니다. 시크릿 모드·브라우저 데이터 삭제 시 익명 인증을 복구할 수 없습니다.
- 수업 코드는 초대 수단입니다. 참여한 조끼리는 질문·응답·피드백을 공유하는 수업 구조이며, 개인 비밀 설문 용도가 아닙니다.
- 서버 기록은 자동으로 만료되지 않습니다. 교사가 결과를 내려받고 수업을 종료한 뒤 ‘수업 기록 삭제’를 실행합니다. 학생 기기에 남은 미제출 초안은 서버 삭제 대상에 포함되지 않습니다.
- 배포 후 실제 교사 기기와 학생 기기 2대 이상으로 한 차시를 진행하고, 학교 Wi-Fi와 iPad Safari에서 QR·키보드·새로고침을 최종 확인해야 합니다.

## 기존 수업과 배포 순서

이전 버전은 실제 Firebase UID와 임의 로컬 UID가 혼재되어 있어 클라이언트가 주장하는 식별자만으로 소유권을 이전할 수 없습니다. 새로 만든 수업에 `schemaVersion: 2`를 기록하며 새 규칙은 이전 수업의 조 자료와 수정 권한을 차단합니다. 이전 자료 자체를 지우지는 않았습니다.

1. 진행 중인 수업을 마치고 필요한 기존 자료를 신뢰할 수 있는 관리자 경로에서 백업합니다. 클라이언트의 로컬 UID를 근거로 일괄 소유권 이전하지 않습니다.
2. Firebase Authentication에서 익명 로그인을 활성화하고, Vercel의 `VITE_FIREBASE_*`가 의도한 프로젝트를 가리키는지 확인합니다.
3. 점검 시간에 `firestore.rules`와 이 프런트엔드를 함께 출시합니다. 새 규칙만 먼저 적용하면 구버전 앱은 쓰기 작업이 차단되므로 수업 중에 단독 적용하지 않습니다.
4. 교사와 학생에게 새로고침 및 **새 수업 코드로 시작**하도록 안내합니다. 이전 수업 기록은 운영자가 관리자 권한으로 조회·백업할 수 있으며, 일반 브라우저에서 임의 인계하지 않습니다.
5. 운영 환경에서 본인 수업 제어, 다른 조 수정 거부, 새로고침 복구, 종료·다운로드·삭제를 확인합니다.

실제 배포 명령과 계정 권한은 운영자가 사용하는 기존 Vercel/Firebase 배포 절차를 따릅니다. 이 작업에서 배포는 실행하지 않았습니다.

## 테스트 재현

Node.js와 Java 21 이상이 필요합니다. 일반 화면 테스트는 Java가 필요하지 않습니다.

```powershell
npm ci
$env:PLAYWRIGHT_CHANNEL='chrome'
npm test
npm run build
npm run lint
npm run test:emulators
```

`test:emulators`는 운영 기본 프로젝트 대신 `demo-question-repair`를 명시하고 로컬 8080/9099 포트를 사용합니다. Java가 PATH에 없으면 해당 실행 환경에 `JAVA_HOME`과 PATH를 설정합니다. 설치된 Chrome을 사용하지 않으려면 Playwright Chromium을 설치한 뒤 `PLAYWRIGHT_CHANNEL`을 생략합니다.

에뮬레이터가 이미 실행 중이면 `node tests/security.mjs`와 `node tests/emulator-browser.mjs`를 **순서대로** 실행합니다. 같은 데모 프로젝트의 데이터를 초기화하므로 두 테스트를 동시에 실행하지 않습니다. `SCREENSHOTS=1`을 지정하면 비공개 로컬 경로 `.dorms-check/private/design/`에 예시 화면을 저장합니다.
